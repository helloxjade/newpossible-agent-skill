# 产品规格 · NewPossible Quiet Radar

## 产品定义

目标用户是没有精力持续追踪技术资讯，但需要及时判断新技术是否改变项目可行性的开发者和技术负责人。

用户维护一张项目目标卡。系统负责查验官方信号、过滤噪音、选择成本最低的验证路径，并且只在出现相关、可执行、值得验证的能力增量时占用用户注意力。

## 核心原则

- 没有值得关注的变化也是有效结果。
- 原始来源可追溯，但不要求用户先阅读资讯流。
- 优先材料、Demo、API 和 CLI；只有需要 GPU 时才使用可用的 NVIDIA GPU 主机。
- 模型负责编写解释，不生成或决定实验命令。
- GPU runner 只执行仓库内预定义任务。
- 通过一个环境门禁不代表候选项目已经有效。

## 比赛场景

参赛主体是 `newpossible-tech-scout` Skill。它将 10 条 NVIDIA 官方信号压缩为 1 个值得验证的候选：cuDF 26.08。Agent 界面展示 Skill 如何过滤、制定实验并产生决定。

Demo Proof Contract：

1. 生成固定种子的 500 万行数据；
2. pandas CPU 与 cuDF GPU 执行相同的过滤和分组聚合；
3. 各运行三轮并取中位数；
4. CPU/GPU 输出通过数值一致性检查；
5. 实测加速达到 1.2x 才给出 `adopt`；
6. 否则返回 `watch` 或 `reject`，不伪造成功。

证据记录候选版本、容器、输入规模、CPU/GPU 耗时、数据传输成本、一致性和当次采用决定。

## API

- `GET /api/bootstrap`：目标卡、信号、过滤汇总、provider 与 GPU 主机状态。
- `POST /api/analyze`：目标卡到唯一 Capability Delta。
- `POST /api/proof`：调用远程 NVIDIA GPU 主机的固定预检任务并保存证据。

## 验收标准

- 首页第一屏说明注意力问题，并显示 10 → 1 的过滤过程。
- 与目标无关的输入返回“今天无需处理”。
- 未连接 GPU 主机时不能产生伪 GPU 证据。
- 远程结果由主服务重新核对，不能依赖 runner 自报的通过状态。
- 完成真实实验后在页面展示并保存 adopt、watch 或 reject 结论与原始指标。
- 桌面与手机页面无脚本错误并保持可读。
